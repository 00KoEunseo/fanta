# 검증 절차

시뮬레이션은 한 곳을 고치면 멀리 떨어진 곳까지 흔들린다. 그래서 고치기 전과 후를 같은 잣대로 잰다.

## 도구

| 명령 | 하는 일 | 시간 |
|---|---|---|
| `npm run check` | 타입 검사 | 수 초 |
| `npm run audit:quick` | 150년 세계 1개 + 생애 4개 | 약 1분 |
| `npm run audit` | 300년 세계 3개 + 생애 16개, 기준선과 비교 | 약 4분 |
| `npx tsx scripts/qa/audit.ts --lives=40` | 생애만 40개 (생애 지표를 큰 표본으로 비교) | 약 6분 |
| `bash scripts/qa/baseline.sh [커밋] [옵션]` | 그 커밋의 코드로 기준선을 다시 만든다 | 위와 같음 |
| `npx tsx scripts/qa/save-size.ts <시드> <년>` | 저장 파일에서 무엇이 자리를 차지하는지 | 약 1분 |
| `npx tsx scripts/qa/contact-check.ts <시드들>` | 첫 조우·첫 교역·첫 전쟁, 소문과 층 발견 | 약 3분 |
| `npx tsx scripts/qa/religion-check.ts <시드들> <년>` | 신앙의 탄생·전파·국교·대신관·성전 명분 | 약 3분 |
| `npx tsx scripts/qa/camp-check.ts <시드들> <년>` | 주둔지 세움·출격·철수·함락, 엇갈린 주둔지 | 약 3분 |
| `npx tsx scripts/qa/paragon-check.ts <시드들> <년>` | 열강의 등장·종족·목적별 행적·도전자 | 약 3분 |
| `npx tsx scripts/qa/diag.ts <시드> <년>` | 층·종족별 인물과 인구, 전쟁 기간·거리·같은 성향, 교역 거리, 천사 일대기 | 약 2분 |
| `npx tsx scripts/qa/demon-check.ts <시드들> <년>` | 악마 예순여섯의 행적, 마족의 수와 노는 비율 | 약 3분 |
| `npx tsx scripts/qa/doom-rate.ts <세계 수> <년>` | 세계 여럿을 돌려 멸망 빈도, 봉인 넷 이상인 달, 전쟁·인물 분포를 잰다 | 24개면 약 15분 |
| `npx tsx scripts/qa/issues.ts <시드들> <년>` | 4차 점검 지표: 전쟁 거리·이웃 비율, 대치·야전·스쳐 지나간 군대, 엇갈린 주둔지, 고대 용·원한·수호룡, 천사의 거취, 마족 수, 반란의 수명과 동참, 심연의 군주, 하늘 용, 성역, 용사와 마왕 | 세계 6개 300년이면 약 40분 |
| `npx tsx scripts/qa/goal-odds.ts <king\|hero\|dl\|all> <생애 수>` | 왕·용사·마왕을 목표로 키울 때 닿는 확률과 실패한 까닭 | 10생애 약 10분 |
| `npx tsx scripts/qa/life-density.ts <생애 수> <시작 번호>` | 탄생 모드의 밀도: 어린 시절 선택지 수·종류, 길 위의 일 종류, 반역·옥살이·추방·함락 소식 | 16생애 약 15분 |
| `npx tsx scripts/qa/compat.ts <저장 파일>` | 예전 코드로 만든 저장 파일을 지금 코드로 불러와 30년 진행·화면·재저장을 확인한다 | 약 1분 |
| `npx tsx scripts/qa/ui-smoke.ts <시드> <년>` | 모든 탭·정보창의 HTML을 만들어 오류·빈 값·조사 표기를 찾는다 (audit에 포함) | 약 1분 |

- 불변식(✗)은 반드시 통과해야 하는 규칙이다. 예: 같은 시드는 같은 결과, 사별은 일대기에 남는다, 미성년은 여행 사건을 받지 않는다.
- 경고(⚠)는 나쁜 신호지만 당장 실패는 아니다. 예: 성능, 명품 쏠림.
- 지표는 기준선 대비 변화율로 본다. ◀는 30% 넘게 변한 것이다. 생애 지표는 표본이 작아 50%를 기준으로 본다.

## 절차

1. **고치기 전:** 작업 트리가 깨끗한지 확인한다(`git status`). 기준선이 직전 커밋과 맞지 않으면 `bash scripts/qa/baseline.sh`로 다시 만든다.
2. **고친 뒤:** `npm run check` → `npm run audit:quick` → `npm run audit` 순서로 돌린다.
3. **영향 점검:** 바꾼 함수·데이터를 쓰는 곳을 모두 찾아 확인한다(`grep`). 특히 아래 항목을 본다.
   - 반환값·인자 모양이 바뀌었는가
   - 난수(`w.rngSim`)를 새로 쓰거나 덜 쓰게 되었는가. 그러면 이후 모든 결과가 달라지므로, 지표 변화가 잡음인지 큰 표본으로 확인한다
   - 저장 파일에 새 필드가 생겼는가. 그러면 `save.ts`에 옛 저장을 위한 보정이 필요하다. 예전 커밋으로 저장 파일을 만들어 `compat.ts`로 확인한다
   - 관전 세계 지표가 바뀌었는가. 플레이어 쪽만 고쳤는데 세계 지표가 움직이면 의도치 않은 연결이 있다는 뜻이다
4. **커밋:** 검증 결과 요약을 커밋 메시지에 남긴다. 기준선은 의도한 변화가 확인된 뒤에만 갱신한다.

## 주의

- `scripts/qa/baseline.sh`는 별도 작업 폴더(`../fanta-base`)의 `node_modules`를 원본에 '연결'한다. 그 폴더를 손으로 지울 때는 반드시 연결부터 끊는다(`cmd //c rmdir ..\fanta-base\node_modules`). 그냥 지우면 원본 `node_modules`까지 지워진다(1단계 중 실제로 한 번 일어났다).

## 알려진 한계

- 한 생애는 아주 작은 변화에도 전혀 다르게 흘러간다(나비 효과). 개별 생애의 결과로 판단하지 말고 평균으로 본다.
- 생애 검증은 고정된 규칙으로 선택지를 고른다. 사람이 고르는 경향과는 다르다.
- 화면은 HTML 문자열까지만 자동 검증한다(ui-smoke). 실제 배치·클릭·캔버스 그림은 브라우저에서 직접 봐야 한다.
